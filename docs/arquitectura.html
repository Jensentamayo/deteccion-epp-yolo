1. Arquitectura general

La solución separa la interfaz de usuario, la comunicación entre componentes y la inferencia del modelo. Streamlit actúa como cliente, mientras que el servicio gRPC encapsula la inferencia realizada por YOLO11n.

Streamlit Interfaz web / Cliente
→
gRPC Comunicación
→
Servicio de inferencia YOLO11n
↓
MLflow Tracking de inferencias y métricas

2. Flujo de inferencia

El siguiente flujo representa el recorrido de una imagen desde la interfaz hasta la respuesta generada por el modelo.

1
Usuario / Cámara
Se obtiene una imagen o frame para realizar la detección.
2
Streamlit
La interfaz recibe la imagen y prepara la solicitud de inferencia.
3
Cliente gRPC
La imagen se envía al servicio de inferencia mediante el contrato definido en inference.proto.
4
Servidor gRPC
El servidor recibe la solicitud y ejecuta el procesamiento correspondiente.
5
YOLO11n
El modelo realiza la detección de las clases no_helmet y no_gloves.
6
MLflow
Se registran métricas y parámetros asociados a la inferencia.
7
Streamlit
La respuesta vuelve al cliente y las detecciones se muestran visualmente mediante cajas de incumplimiento.

3. Organización de componentes

Vista

  • Streamlit
  • Captura de imágenes
  • Visualización

Servicio

  • gRPC
  • Protocol Buffers
  • Cliente y servidor

Modelo

  • YOLO11n
  • Inferencia
  • Detección EPP

4. Clases detectadas

no_helmet

Detecta situaciones en las que una persona no utiliza casco de seguridad.

no_gloves

Detecta situaciones en las que una persona no utiliza guantes de seguridad.

Salida

Las detecciones de incumplimiento se representan mediante cajas de color rojo en la interfaz.
